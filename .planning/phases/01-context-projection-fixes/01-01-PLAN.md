In `TokenHealthMonitor.swift`, in the `assess()` method after line 134, add downward tier adjustment logic. The existing upward check stays unchanged. After it, add an `else` branch for downward adjustment:

```swift
let observedTokens = inputTokens + cacheReadTokens + cacheWriteTokens + outputTokens
let tiers = [200_000, 500_000, 1_000_000, 2_000_000, 5_000_000]
if observedTokens > contextWindow {
    // Upward: session exceeds known window (existing logic, unchanged)
    contextWindow = tiers.first(where: { $0 > observedTokens }) ?? observedTokens * 2
} else if let lowerTier = tiers.last(where: { $0 >= observedTokens }),
          lowerTier < contextWindow {
    // Downward: observed tokens fit in a smaller tier than the default/lookup tier.
    // Only downgrade if observed tokens are below the next-lower tier boundary,
    // which prevents thrashing on sessions that just happen to be early/small.
    // The `tiers.last(where: >= observed)` finds the smallest tier that fits.
    contextWindow = lowerTier
}
```

Wait — `tiers.last(where: { $0 >= observedTokens })` would give the LARGEST tier >= observed, which is wrong. We need the SMALLEST tier >= observed. That's `tiers.first(where: { $0 >= observedTokens })`. But we also need a guard against thrashing — don't downgrade for sessions with very few tokens (e.g., a brand new session with 1000 tokens shouldn't force the tier to 200K when the model actually has 1M).

Per the user decision: "Downward adjustment should only trigger when observed tokens are significantly below the current tier (e.g., observed < tier_below_current)."

Implementation: Find the tier one step below the current contextWindow. If observedTokens < that lower tier, downgrade. Otherwise keep the current tier (session hasn't proven it's on a smaller window).

```swift
let observedTokens = inputTokens + cacheReadTokens + cacheWriteTokens + outputTokens
let tiers = [200_000, 500_000, 1_000_000, 2_000_000, 5_000_000]
if observedTokens > contextWindow {
    // Upward: session exceeds known window
    contextWindow = tiers.first(where: { $0 > observedTokens }) ?? observedTokens * 2
} else if let currentIndex = tiers.firstIndex(of: contextWindow),
          currentIndex > 0 {
    // Downward: check if observed tokens are below the next-lower tier,
    // which strongly indicates the session is on a smaller context window.
    let lowerTier = tiers[currentIndex - 1]
    if observedTokens < lowerTier {
        // Find the smallest tier that still fits the observed tokens
        contextWindow = tiers.first(where: { $0 >= observedTokens }) ?? tiers[0]
    }
}
```

This means: for a 1M default window, the lower tier is 500K. Only if observedTokens < 500K do we downgrade. Then we find the smallest tier >= observed (e.g., 150K tokens -> 200K tier).
