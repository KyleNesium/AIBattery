    **1. Add `FileCacheSummary` struct inside SessionLogReader:**

    **Wait — on closer analysis, the problem is different.** UsageAggregator needs per-entry iteration for date grouping, project accumulation, windowed token bucketing, and TokenHealthMonitor. A pure summary (aggregated totals) would lose the ability to do date-based windowing.

    **Revised approach — store lightweight entries without gitBranch (unused in aggregation):**

    Actually, `AssistantUsageEntry` is already quite lean (11 fields, all value types). The real memory hog is holding 3,103 arrays of entries in `cache` AND a merged copy in `cachedAllEntries`. The merged copy duplicates every entry.

    **The actual fix: eliminate the `cachedAllEntries` duplication.**

    Currently `readAllUsageEntries()` builds `allEntries` array (copy of all entries) AND stores it in `cachedAllEntries`. For 3,103 files this means every `AssistantUsageEntry` exists twice in memory.

    **Implementation:**

    1. Change `cachedAllEntries` from `[AssistantUsageEntry]?` to a wrapper that is built lazily from the per-file cache on demand, rather than storing a separate copy. Since the per-file cache already holds all entries, the merged result can be reconstructed from it without duplication.

    2. Better approach: Keep `cachedAllEntries` but make it the ONLY source of entries after merge. After building `cachedAllEntries`, release the raw entry arrays from the per-file cache for files not modified today. The per-file cache retains only `(modDate, fileSize, entryCount)` — enough to know whether to re-parse on next cycle.

    **Concrete changes to SessionLogReader.swift:**

    a. Change cache type from `[String: (Date, UInt64, [AssistantUsageEntry])]` to:
    ```swift
    private var cache: [String: FileCacheEntry] = [:]

    struct FileCacheEntry {
        let modDate: Date
        let fileSize: UInt64
        /// Raw entries — nil after eviction (old files). Re-parsed if file changes.
        var entries: [AssistantUsageEntry]?
        /// Message IDs from this file — retained after eviction for deduplication.
        var messageIds: Set<String>
    }
    ```

    b. In `readAllUsageEntries()`, after building `cachedAllEntries`, evict raw entries from files whose modDate is before today:
    ```swift
    let today = Calendar.current.startOfDay(for: Date())
    for (path, var entry) in cache {
        if entry.modDate < today && entry.entries != nil {
            var updated = entry
            updated.entries = nil
            cache[path] = updated
        }
    }
    ```

    c. In `cachedRead()`, when `cache[path]` has matching fingerprint but `entries == nil` (evicted), check if the file was modified today. If not, return empty array (entries already merged into cachedAllEntries). If yes (file changed after eviction), re-parse.

    d. The key insight: `cachedAllEntries` is the authoritative merged result. When `isDirty == false`, it's returned directly. When `isDirty == true`, we rebuild from per-file cache entries (non-nil) + re-parse any files that changed. Files with `entries == nil` and unchanged fingerprint don't need re-parsing because their entries are already in `cachedAllEntries` from the previous cycle.

    **Wait — this won't work if cachedAllEntries is invalidated.** On invalidation, isDirty=true and cachedAllEntries is implicitly stale. If entries are evicted from per-file cache, we can't rebuild.

    **Final correct approach:**

    Keep `cachedAllEntries` as the master copy. On invalidation (isDirty=true), DON'T clear cachedAllEntries. Instead, on next readAllUsageEntries():
    - For files with entries != nil (today's files, recently parsed): use those entries
    - For files with entries == nil (evicted old files) AND unchanged fingerprint: their entries are already in cachedAllEntries, skip
    - For files with entries == nil AND changed fingerprint: re-parse (file was modified)
    - For deleted files: remove from cache, rebuild cachedAllEntries without their entries

    This requires tracking which messageIds came from which file, so deleted/changed files can have their old entries removed from cachedAllEntries.

    **Simplest correct implementation:**

    1. Add `messageIds: Set<String>` to per-file cache entry
    2. After merge into cachedAllEntries, evict `entries` array for old files (keep messageIds + fingerprint)
    3. On dirty rebuild: for evicted files with same fingerprint, skip re-parse (their messageIds are in the dedup set, their data is in cachedAllEntries). For changed/new files, re-parse normally.
    4. When a file is deleted or its fingerprint changes AND entries is nil, must re-parse to get fresh entries. Remove old messageIds from the dedup set.

    **Even simpler — just don't store entries twice:**

    The real duplication is: per-file cache holds entries AND cachedAllEntries holds the same entries merged. After the first successful merge:
    - cachedAllEntries = authoritative merged array
    - Per-file cache: keep (modDate, fileSize) only — drop entry arrays entirely for ALL files
    - On next dirty cycle: only re-parse files whose fingerprint changed; for unchanged files, their entries are already in cachedAllEntries

    Implementation:
    ```swift
    // After building cachedAllEntries successfully:
    // Release all per-file entry arrays — fingerprints retained for change detection
    for key in cache.keys {
        cache[key] = FileCacheEntry(
            modDate: cache[key]!.modDate,
            fileSize: cache[key]!.fileSize,
            entries: nil
        )
    }
    ```

    On dirty rebuild in readAllUsageEntries():
    ```swift
    // Start from previous cachedAllEntries if available
    var baseEntries = cachedAllEntries ?? []
    var baseIds = Set(baseEntries.map(\.messageId))

    // Only re-parse files that changed (fingerprint mismatch or new)
    for fileURL in jsonlFiles {
        let path = fileURL.path
        let attrs = try? FileManager.default.attributesOfItem(atPath: path)
        let modDate = attrs?[.modificationDate] as? Date
        let fileSize = attrs?[.size] as? UInt64

        if let cached = cache[path],
           cached.modDate == modDate,
           cached.fileSize == fileSize {
            // Unchanged — entries already in baseEntries, skip
            continue
        }

        // Changed or new — re-parse
        let entries = readSessionFile(at: fileURL)
        cache[path] = FileCacheEntry(modDate: modDate ?? Date(), fileSize: fileSize ?? 0, entries: nil)
        for entry in entries {
            if baseIds.insert(entry.messageId).inserted {
                baseEntries.append(entry)
            }
        }
    }

    // Remove entries from deleted files
    // (handled by stale key removal already cleaning cache)

    baseEntries.sort { $0.timestamp < $1.timestamp }
    cachedAllEntries = baseEntries
    ```

    This eliminates the double-storage entirely. Per-file cache becomes fingerprint-only after first merge.

    **Implement this approach.** Key changes:
    - Replace cache tuple type with a lightweight struct `FileCacheEntry` that has `modDate: Date`, `fileSize: UInt64`, `entries: [AssistantUsageEntry]?`
    - After successful merge into cachedAllEntries, nil out all `entries` in the per-file cache
    - On dirty rebuild, use cachedAllEntries as base, only re-parse changed files incrementally
    - Handle file deletion: track which files contributed to cachedAllEntries; when stale keys found, set a flag to force full rebuild from re-parsed files only

    Thread safety: all changes remain inside the existing `lock.lock()` / `lock.unlock()` scope in readAllUsageEntries().
