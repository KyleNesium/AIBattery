<objective>
Defer rendering of heavy sections (InsightsGate, ProjectUsageGate) until after the panel is visible on screen.

Purpose: RESP-04 requires lazy-loading heavy sections. InsightsGate computes chart data transforms on body evaluation, and ProjectUsageGate runs sort computation. Both fire synchronously during makeKeyAndOrderFront, blocking the panel from appearing. Deferring them by one run-loop iteration lets the panel show the lightweight header+bars first, then renders heavy sections one frame later — invisible to the user but eliminates blocking the open path. This also addresses RESP-02 (no UI freeze) by removing the heavy computation from the critical show path.

Output: Updated UsagePopoverView.swift with deferred rendering, plus unit tests for the state logic.
</objective>

```swift
/// Tracks whether the panel has completed its initial render pass.
/// Heavy sections gate on `hasAppeared` to defer rendering by one run-loop iteration.
struct DeferredRenderState {
    private(set) var hasAppeared: Bool = false

    mutating func appeared() {
        hasAppeared = true
    }

    mutating func disappeared() {
        hasAppeared = false
    }
}
```

2. **Add `@State private var panelHasAppeared = false`** to UsagePopoverView (line ~7, alongside other @State properties).

3. **Gate InsightsGate and ProjectUsageGate** behind the flag. In `mainContent`, replace lines 149-150:

The `if` branch means SwiftUI will NOT instantiate these views at all on the first frame. This is critical — `.hidden()` would still render. The `if false` branch tells SwiftUI to skip instantiation entirely.

4. **Add deferred appearance trigger.** Update the existing `.onAppear` on the mainContent VStack (line 200):

```swift

// After:

}
```

The `DispatchQueue.main.async` defers the state mutation to the NEXT run-loop iteration. This means:
- Frame 1: Panel appears with header + metric toggle + usage bars (lightweight)
- Frame 2: panelHasAppeared flips true, InsightsGate + ProjectUsageGate render

This is invisible to the user but removes chart computation from the makeKeyAndOrderFront call stack.
